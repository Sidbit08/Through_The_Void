# Private event-day checklist

Use a fresh rehearsal copy before using the real event database. Keep organizer documents, ZIPs, source and screenshots off participant PCs.

- Install Python and pinned dependencies on the host before disconnecting the internet. Run `manage.py check` and the automated suite. Verify the organizer account and securely distribute unique participant access codes. Do not start the real clock during rehearsal.
- Test from actual Linux participant PCs in both Chromium and Firefox. Check the door and white-star targets, source viewing, new image tabs, file saving, level 2 scrolling/select-all, original image inversion, GIF animation and every MP3 download. Keep browser developer tools and right-click enabled.
- **Listen to all voice clues:** play the hint normally; slow the two `4x` clips to one-quarter speed and the two `3x` clips to one-third speed in an approved tool. Confirm each expected line in the organizer guide and the appended digits seven, two, nine, four in level order. Check pitch-aware slowdown settings and headphones/speakers. Cloud checks verified original packet preservation and recognized the four slowed appended digits; original poem/hint transcription and physical audio output still need listening.
- Test Morse decoding with an approved tool and the actual animated relative music link. Ensure the participant machines have the necessary approved offline image, audio and ASCII/Morse tools already installed.
- Use managed participant browser profiles with extension installation restricted. Restrict administrator/root access on participant PCs. Disable unapproved extensions through device policy; a webpage cannot reliably discover arbitrary AI extensions.
- If deploying the [Linux Event Mode toolkit](../tools/event-mode/README.md), complete its separate one-PC pilot and confirm each PC's activation. Do not enable it during a live event without a recovery console; check reboot, failure, policy and rollback behavior on the actual lab image.
- Configure network allowlists yourself. Allow Google search and approved solver domains separately: allowing Google does not permit every result's target site. Google may itself display AI features; a domain-only allowlist is not a complete AI ban. Decide whether to use a managed search surface and supervision. Test the actual restrictions on participant accounts, including direct IP access and alternative browsers.
- Supervise the separate unrestricted AI station. Verify participant identity, check remaining allowance in organizer control, record each prompt atomically, and supervise submission. Allow three prompts total across all six hours. Use a written reason for any correction. Agree on a personal-device policy and communicate it before launch.
- Verify laptop LAN address and stable addressing, network client isolation, host firewall allowance, and port selection. Do not expose the application to the public internet. If using HTTPS, install and test the certificate on every client. The application does not alter network configuration.
- Plug in the laptop, disable automatic sleep for the event, verify available disk space and correct host time, and arrange a consistent private backup. Use `manage.py backup` rather than copying a running database alone. Practice recovery in a separate copy and save CSV exports periodically.
- Rehearse simultaneous access with your intended participant count. The cloud tests include concurrent AI-ledger updates and gate cooldown enforcement but do not constitute a capacity/load test of your laptop, switch or Wi-Fi.
- At launch, use organizer control's explicit start action. Confirm the displayed UTC deadline and its local-time equivalent. Share only the participant entry address. The poster's date/time is decorative; the server's start action controls the six-hour window.
- After six hours, verify new unlocks/completions are refused, export results and audit logs, take a final consistent backup, and retain the original database. Do not reset the clock to extend a live event.
